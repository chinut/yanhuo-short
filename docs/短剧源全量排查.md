# 短剧源全量排查与选型（2026-10 实测）

需求：**要能全部看，不要只能看几集的那种。**
本文是为此做的全网源排查记录，所有结论都来自真实请求。

脚本：`tools/probe_candidates.py`、`probe_deep.py`、`probe_more_sources.py`、
`probe_ecosystem.py`、`probe_qimao_params.py`、`probe_sources.py`

---

## 最终结论

| 角色 | 源 | 实测 |
|---|---|---|

## 一、主源为什么是七猫：全集实测

验收标准只有一条：**每一集是不是都有可播地址。**

```
剧名：《潜龙出山，闪婚美女总裁》
标注集数        96
play_list 实际   96
有非空地址       96          ← 一集不缺
抽查  第 1 集    HTTP 206  application/vnd.apple.mpegurl  ✅
      第 49 集   HTTP 206  application/vnd.apple.mpegurl  ✅
      第 96 集   HTTP 206  application/vnd.apple.mpegurl  ✅
备案号          （七猫）网微剧备字（2025）第01177号
```

**App 内实测**（Pixel 7 / Android 17，release 包）：

```
[SourceRegistry] 第 1 集  ← 七猫短剧（直取）
[SourceRegistry] 第 10 集 ← 七猫短剧（直取）      ← 红果在这一集是 404
截图：docs/shots/22-qimao-ep10.png（画面正常、有字幕）
```

### 内容规模

接口没有"浏览全部"，只能按名字搜，所以规模要靠关键词覆盖来算：

```
单个热词翻页深度
   总裁 / 战神 / 重生   各 12 页有效，各去重 120 部

多关键词覆盖
   42 个关键词 × 2 页   → 去重 713 部
```

后续把推荐流的关键词表扩到 **48 个**，首页可以一直往下翻。

### 字段完整度（够撑起整个界面）

```
搜索条目：id / title / image_link / total_num / sub_title / hot_value / label_name
详情字段：title / image_link / intro / tags / total_episode_num / play_list
          own_record_number（备案号）/ is_over / creator / follow_count / share_count
play_list：video_id / video_url / video_h265_url / duration / width / height
           / first_img / sort / status
         实测单集 720×1280，77 秒
```

`hot_value` 是关键补充：**接口没有榜单，但有条目热度**，所以热门榜是自己按它算的。

## 二、备用源红果：为什么降级

```
详情页  accessible_episode_cnt = 3      ← 实测多部剧恒为 3
播放页  第 1/2/3 集  HTTP 200 有 main_url
        第 4 集      HTTP 404
        第 5/10 集   HTTP 404
```

试过《首辅娇娘》69 集、《少夫人的乌鸦嘴又显灵了》80 集、《我的婆婆，我罩着》108 集
—— **全部只有 3 集**。这是站点商业付费墙，客户端突破不了。

留下它的理由：七猫的 713 部没收录的剧，红果可能正好有，能播 3 集总比什么都看不了强。
回退发生在播放器里，界面上会标明「由红果短剧提供」，不偷偷换源。

要么是红果 App 的签名接口（需要逆向下图中的反爬）：


（友商 App「各种果」的逆向细节见 [友商App逆向分析.md](友商App逆向分析.md) ——
它同样受 3 集限制。）

## 四、踩过的坑

1. **七猫接口只认 `name=`**：无参数、`type=`、`id=1` 全都返回空或报错。
   所以**没有浏览/榜单能力**，首页推荐流必须是"多热词轮转"。
2. **推荐流和搜索页的缓存 key 号段不同**会导致同一部剧请求两次。
   现在两边统一走 `cachedSearch(keyword, page)`，key 只有一个来源。
3. **换主源时必须同时检查 `cached()`**。七猫原来作为备用源返回 `emptyList()`
   （"备用源内容没必要落盘"），一旦提为主源，立刻表现为
   **断网启动首页全白**。现在和红果共用一个 `DramaLibrary`，用 `sourceId` 区分。
4. **热度不能按字符串排序**：`"9万"` 字典序在 `"1000万"` 前面。
   必须把「5525万」折算成数值（`parseHot`）再排。
5. **文案不能写死源名**。热剧榜原来写死"红果热播"，换源后就成了错误信息，
   现在改成 `${primary().displayName} · 热度排序`。
6. **证书**：七猫的证书由 Let's Encrypt `YR1` 签发，**Android 9 及更早没有对应根证书**，
   https 握手会失败。实测纯 HTTP 也返回 200，所以实现是「https 优先，失败退 http」。
   不用"放宽证书校验"（那会全局接受任意证书）。
