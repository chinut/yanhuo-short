# 短剧数据源分析（2026-10 实测）

本文是**先验证、后设计**的产物。所有结论都来自真实请求，脚本见
`tools/probe_sources.py`、`tools/probe_html.py`、`tools/probe_rank.py`、`tools/probe_qimao.py`。

## 一、主源：红果短剧官网（hongguoduanju.com）

### 为什么是"爬官网"而不是调 App 接口

红果 App 走不通（Flutter 编译产物、接口要 sign 签名、还有证书固定，
抓包 0 条日志）。但**官网是服务端渲染的，数据就在 HTML 里**。

### 实测链路

| 用途 | 地址 | 拿到什么 |
|---|---|---|
| 分类列表 | `/category/{slug}?page=N` | 一页 24 部：`series_id` / 剧名 / 封面 / **全 N 集** / 题材标签 |
| 热剧榜 | `/rank/hot-real-drama` | 20 部，带**名次**和「6721万热度」 |
| 详情 | `/detail?series_id={sid}` | `vid_list` **全部分集 id** + `episode_cnt` + 简介 |
| 播放 | `/player/{sid}/{vid}` | `video_player_info.main_url` —— **直连 MP4** |
| 搜索 | `/search/{关键词}` | 一页 10 部 |

```
实测记录（2026-10-09）
  首页            HTTP 200，140969 字符，series_id 唯一 32 个
  分类 real-drama HTTP 200，251475 字符，24 部
  分类 page=2/3   各 24 部（分页有效）
  排行榜          HTTP 200，20 部，名次 1~20
  搜索「总裁」     HTTP 200，80103 字符，命中 10 部
  详情《首辅娇娘》 episode_cnt=69，vid_list=69 条
```

### 播放地址本身（不是 m3u8）

```
main_url = https://v3-hgweb.qznovelvod.com/.../video/tos/cn/...
实测：
  HTTP 206
  Content-Type: video/mp4
  前 16 字节 000000206674797069736f6d → "ftypisom"，标准 MP4
  分辨率 720×1280（竖屏），时长 112 秒
```

**不需要 m3u8、不需要解密、不需要签名**，ExoPlayer 直接就能播。

### ⚠️ 硬约束：每部剧只免费前 3 集

这是本次勘查**最重要的发现**，也是整个 App 数据层设计的出发点。

```
详情页  accessible_episode_cnt = 3      ← 实测恒为 3
播放页  第 1 集  HTTP 200  → 有 main_url
        第 2 集  HTTP 200  → 有 main_url
        第 3 集  HTTP 200  → 有 main_url
        第 4 集  HTTP 404  ← 服务端直接拒绝
        第 5 集  HTTP 404
        第 10 集 HTTP 404
```

试过多个不同的剧（《首辅娇娘》69 集、《少夫人的乌鸦嘴又显灵了》80 集、
《我的婆婆，我罩着》108 集），**全部是 3 集**。

这是站点的商业付费墙，**客户端突破不了**。所以：

- 列表/详情**照实显示全部集数**（"全 108 集"），不隐瞒、不改成 3
- 免费集之外自动尝试备用源（见下）
- 备用源也找不到就**如实告诉用户看不了**，不偷偷换成别的剧

### 踩过的坑

1. **分集列表是懒加载的**：详情页 DOM 里只有 2~3 个 `<a>`，但 `vid_list` 有 108 个。
   滚动、"查看全部"都没用 → **不要解析 DOM，直接正则抽 `vid_list` 数组**。
2. **取播放地址必须用普通 GET，不能用浏览器**：用真实浏览器打开时视频变成
   `blob:`（MSE），`main_url` 反而取不到。反直觉，但实测如此。
3. **详情页 HTML 体积不稳定**：255KB / 470KB / 539KB 都见过，
   所以解析一律容错，失败要留**具体**日志。
4. **URL 里的斜杠是转义的**：`https:\u002F\u002Fp3-novel...`，取值时要还原。
5. **类名带哈希且每版都变**（`pc-card-DQXf3W` / `m-card-V7QopP`），
   所以解析**按 `series_id` 位置切块**，不按 DOM 结构 —— 只要"链接还在"就一直能用。
6. **榜单页和分类页结构不一样**：榜单是 `<ol><li>`，剧名在 `<h2>` 里，
   而且**不提供集数**（集数只在详情页有）。所以首页热榜卡片的集数要额外补。

## 二、备选源：七猫短剧接口

### 为什么需要它

红果只免费 3 集，必须有个地方接着看。这个接口实测能拿到**全集直链**：

```
接口  https://xiaoqi.icofun.cn/API/qimao_duanju.php
  ?name=关键词&page=N  → 搜索（返回 data.list）
  ?id=短剧id           → 全部集直链（返回 data.play_list）

实测记录（2026-10-09）
  搜索「总裁」           → 10 部
  《潜龙出山，闪婚美女总裁》标注 96 集 → play_list 96 条 → 全部有地址
  第 1 集  HTTP 206  application/vnd.apple.mpegurl（HLS）
  最后一集地址非空
  备案号：（七猫）网微剧备字（2025）第01177号
```

**内容是正规的** —— 返回里有网微剧备案号，地址在七猫自己的 CDN
（`cdn-vod-playlet.wtzw.com`），不是盗链聚合。

### 局限

1. **没有"浏览全部"**，只能按名字搜。所以它的"推荐流"是用一组题材热词
   （总裁 / 战神 / 重生 …）各搜一页，翻页时按顺序轮转、合并去重。
   这是接口能力决定的，不是偷懒。
2. **没有榜单**，所以热剧榜只能交给红果。
3. **库不同**：实测红果首页/热榜的 42 部与七猫热词池的 187 部
   **交集为 0** —— 两个平台的版权库基本不重叠。

### ⚠️ 证书问题

服务器证书由 **Let's Encrypt 的 `YR1`** 签发，**Android 9 及更早的系统根证书库里
没有对应 CA**，老机器上 https 握手直接失败：

```
SSLHandshakeException: Trust anchor for certification path not found.
```

实测这个接口**纯 HTTP 也返回 200**，所以实现里是「https 优先，证书/网络类失败
就退回 http」。**不用**"放宽证书校验"——那是全局接受任意证书，中间人风险大得多；
而这里只传公开的短剧元数据，不涉及任何用户信息。

## 三、评估过但没接入的源

| 源 | 地址 | 结论 |
|---|---|---|
| **红果镜像（苹果CMS）** | `www.hongguoapp.cn` | 结构完整（`/voddetail/{id}.html`、`/vodplay/{id}-1-{ep}.html`，`player_aaaa.url` 是 m3u8），但**服务端极不稳定**：实测同一批请求里出现 `IncompleteRead`、`HTTPError 403/502`、`SSL: UNEXPECTED_EOF_WHILE_READING`、超时。不适合做产品依赖 |
| **红果 API（第三方）** | `api-v2.cenguigui.cn/api/duanju/api.php` | 提供红果的搜索/详情/播放解析，但**本机连不上**（TLS 握手失败，curl 与 PowerShell 都空响应），无法验证可用性 |
| **红果官网（App 接口）** | —— | 要 sign 签名 + 证书固定，抓包 0 条日志，放弃 |

> 需求里说"如果没有红果源的话就用 APP 的源"—— 实测**红果官网源可用**，
> 所以主源用红果，七猫作为免费集之外的兜底。

## 四、结论：App 的数据层怎么设计

```
用户点第 4 集
  │
  ├─ 红果 /player/{sid}/{vid}  →  HTTP 404（付费墙，正常现象，不报错）
  │
  ├─ 备用源按剧名匹配
  │     ① 先查本地片库（不联网）
  │     ② 再搜七猫接口（前两页候选）
  │     ③ TitleMatch 归一化打分：完全相等 1000 / 一方包含另一方 500+长度 / 否则 0
  │     ④ 分数为 0 → 宁可承认"没找到"，也不猜（猜错会让用户看到另一部剧）
  │
  ├─ 命中 → 取该剧**全集直链**（一次请求），缓存到内存，后续几集不再走网络
  │         播放，并在界面上标注「由 七猫短剧 提供」—— 换源要说出来
  │
  └─ 未命中 → 显示"这一集需要会员。红果只免费前 N 集，也没能在其他源匹配到这部剧。"
```

**关键设计取舍**：

- **地址不提前取**：带时效签名，提前取了等于白取。点哪集取哪集。
- **只信详情页的集数**：列表页的"全 N 集"是抓取时的快照，可能滞后；
  详情页的 `episode_cnt` 才是当前真实值。连载更新检测据此判断。
- **集数只增不减**：热榜页给不出集数（返回 0）时不能把列表页给出的 69 覆盖成 0。
  这个规则同时让"集数变大 = 有新集"变得可直接判断。
- **两个源都可能返回纯数字 id**，所以本地唯一键是 `sourceId:targetId`，
  不加源前缀会串（收藏了红果的 A，点开变成七猫的 B）。
