# 发布与自动升级说明

## 一、两个仓库的分工

| 仓库 | 地址 | 放什么 |
|---|---|---|
| **GitHub（主）** | https://github.com/chinut/yanhuo-short | **全部源码** + Release（APK） |
| **Gitee（仅发布）** | https://gitee.com/chinut/yanhuo-short | **只有 Release 附件（APK）**，无源码 |

Gitee 侧刻意不放源码 —— 仓库里只有 `README.md` 和 `releases/` 目录（放安装包的镜像）。
这样"源码在主仓库、下载走国内镜像"两边都合适。

## 二、App 怎么升级（实现说明）

代码在 `app/src/main/java/com/chinut/yanhuo/update/`：

| 文件 | 职责 |
|---|---|
| `UpdateChecker.kt` | 读**版本清单**（JSON），解析出最新版本与候选下载地址 |
| `UpdateInstaller.kt` | 依次试各下载源下载 APK，经 FileProvider 唤起系统安装器 |

### 为什么读"清单"而不是直接读 GitHub/Gitee 的 Release API

1. **API 有限流** —— GitHub 未认证 60 次/小时/IP，被限流会被误判成"没有新版本"；
2. **两个源格式不同**，直接读要写两套解析；
3. **下载通道要能回退** —— 清单里可以同时列 GitHub、Gitee 两条地址，
   App 按顺序试，哪个通用哪个。这是"通过 GitHub 和 Gitee 升级"的稳妥做法。

### 清单地址

```
https://raw.githubusercontent.com/chinut/yanhuo-short/main/docs/update-manifest.json
```

源码在 `docs/update-manifest.json`，**改完提交即生效**（无需重新编译 App）。

### 清单格式

```json
{
  "versionCode": 4,
  "versionName": "1.1.0",
  "notes": "更新说明（显示在升级弹窗里）",
  "urls": [
    "https://github.com/.../releases/download/v1.1.0/xxx.apk",
    "https://gitee.com/.../releases/download/v1.1.0/xxx.apk"
  ]
}
```

`urls` **按优先级排列**，App 顺序尝试；单条失败会换下一条（实测 GitHub 在部分
网络下会超时，所以 Gitee 那条是必要的兜底）。

## 三、发新版本的完整步骤

```powershell
$env:JAVA_HOME="E:\Program Files\Android\Android Studio\jbr"
cd G:\android\AndroidGuo

# 1) 改版本号（versionCode 必须 +1，否则系统拒绝覆盖安装）
#    app/build.gradle.kts: versionCode / versionName

# 2) 构建 + 跑测试
.\gradlew.bat clean :app:testDebugUnitTest :app:assembleRelease

# 3) 改名（Release 附件用统一命名）
Copy-Item .\app\build\outputs\apk\release\app-release.apk .\yanhuo-short-v1.1.0.apk

# 4) 提交源码 + 打标签 + 推送
git add -A; git commit -m "发布 v1.1.0"; git tag -f v1.1.0
git push origin main; git push -f origin v1.1.0

# 5) 建 GitHub Release 并上传 APK（用 token 走 API，见下）
# 6) 建 Gitee Release 并上传附件（用私人令牌走 API，见下）
# 7) 更新 docs/update-manifest.json 里的 versionCode/versionName/urls 并提交
```

### 第 5/6 步的 API 调用（本机已存好凭据，可直接复用）

凭据存在 Windows 凭据管理器（`git:https://github.com` 与 `git:https://gitee.com`），
取法：

```powershell
$ghToken = (@("protocol=https","host=github.com","","") | git credential fill 2>&1 |
            Select-String "^password=").Line -replace "^password=",""
$gtToken = (@("protocol=https","host=gitee.com","","") | git credential fill 2>&1 |
            Select-String "^password=").Line -replace "^password=",""
```

**GitHub**：

```powershell
# 建 Release（返回里有 id 与 upload_url）
curl.exe -X POST -H "Authorization: token $ghToken" -H "User-Agent: yanhuo" `
  -H "Accept: application/vnd.github+json" `
  --data-binary "@release.json" `
  "https://api.github.com/repos/chinut/yanhuo-short/releases"

# 传附件（注意是 uploads.github.com，且 upload_url 要删掉末尾的 {?name,label}）
curl.exe -X POST -H "Authorization: token $ghToken" -H "User-Agent: yanhuo" `
  -H "Content-Type: application/vnd.android.package-archive" `
  --data-binary "@yanhuo-short-v1.1.0.apk" `
  "https://uploads.github.com/repos/chinut/yanhuo-short/releases/<id>/assets?name=yanhuo-short-v1.1.0.apk"
```

**Gitee**（顺序不能颠倒，空仓库建 tag 会报"起点不存在"）：

```powershell
# 1) 先建 tag（refs 必须是已存在的分支）
curl.exe -X POST -H "Content-Type: application/json;charset=UTF-8" `
  --data-binary "@tag.json" `
  "https://gitee.com/api/v5/repos/chinut/yanhuo-short/tags?access_token=$gtToken"
#    tag.json: {"refs":"main","tag_name":"v1.1.0","tag_message":"..."}

# 2) 建 Release
curl.exe -X POST -H "Content-Type: application/json;charset=UTF-8" `
  --data-binary "@release.json" `
  "https://gitee.com/api/v5/repos/chinut/yanhuo-short/releases?access_token=$gtToken"

# 3) 传附件（multipart，端点用 release id）
curl.exe -X POST -F "file=@yanhuo-short-v1.1.0.apk;type=application/vnd.android.package-archive" `
  -F "access_token=$gtToken" `
  "https://gitee.com/api/v5/repos/chinut/yanhuo-short/releases/<id>/attach_files"
```

验证（应返回 200/206 且是安装包）：

```powershell
curl.exe -sI -L "https://github.com/chinut/yanhuo-short/releases/download/v1.1.0/yanhuo-short-v1.1.0.apk"
curl.exe -sI -L "https://gitee.com/chinut/yanhuo-short/releases/download/v1.1.0/yanhuo-short-v1.1.0.apk"
```

## 四、踩过的坑（都实际遇到过）

1. **Gitee 空仓库不能先建 tag** —— 报 `起点不存在`。必须**先有提交**
   （哪怕只放一个 README），才能建 tag → Release。
2. **Gitee 仓库里的大文件不能匿名下载** —— 直接放 `releases/xxx.apk` 再走
   `/raw/` 会返回 `403 large file require login for access`。
   **必须走 Release 附件**，附件下载才不需要登录。
3. **Gitee 没有 `attach_files` 的公开文档入口**，且端点必须用 **release id**
   （用 tag 名会 405/404）。
4. **GitHub 上传附件是 `uploads.github.com`**，不是 `api.github.com`；
   且响应里的 `upload_url` 带 `{?name,label}` 模板，要先删掉。
5. **`gh`/`gitee` CLI 都没装**，只能走 API + `git credential fill`。
6. **git 配了本地代理** `http://127.0.0.1:7888`（Clash 类），
   push 与 API 调用都走它 —— 代理没开时 push 会失败。

## 五、安全提醒

- **`app/yanhuo.jks` 连同密码一起在仓库里**（`build.gradle.kts` 里写着
  `storePassword = "yanhuo123"`）。这是自用/学习项目的刻意取舍（换机器能继续签名），
  但**不要把这个 keystore 用于任何正式上架的应用**。
- `local.properties` 已被 `.gitignore` 排除；构建**不依赖它**
  （`build.gradle.kts` 里没有引用），别人 clone 后本机装了 Android SDK 即可构建。
