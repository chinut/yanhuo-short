## 三、最关键的一次实测：伍果「只有第 1 集」

伍果是**唯一被我完整跑通**的站：搜索可用（`?wd=`）、m3u8 直链真实可取。
所以拿它做付费墙边界扫描（`tools/probe_wall.py`）：

```
扫描 https://www.duanju55.com  vod=55288  sid=1  nid=1..30

  ✓ nid=1    ok      https://lzv34.com/20261009/8903_456237ac/index.m3u8
  ✗ nid=2    empty   trysee=0 points=0
  ✗ nid=3    empty   trysee=0 points=0
  …（3~30 全 empty）
  统计: {'ok': 1, 'empty': 29}
```

**并且做了反证**：换 `sid=2`、`sid=3` 复核，结果依旧 `empty` ——
排除了"线路选错"这一解释。所以这不是我的解析问题。

这条规律和红果官网**一模一样**：免费给一集，后面要授权。
`trysee=0`（无试看）、`points=0` 说明也不是积分墙，就是"不给"。

> 判据价值：`player_aaaa` 里 `url` 为空 = 站点不给这一集的公开地址。
> 这比数选集列表可靠得多（选集列表常是 AJAX 懒加载，数不到）。

## 四、目录可解析的 4 个站（`tools/probe_catalog.py`）

| 源 | 目录 URL（抄自上游 Go 路由表） | 条目 | 集数线索 |
|---|---|---|---|
| 网果 | `/show/duanju-----------.html` | 48 | 列表页无 |
| 伍果 | `/` | 128 | 列表页无 |
| 归片 | `/` | 153 | 63 处（但噪声大） |
| 韩小圈 | `/` | 736 | 列表页无 |

**注意**：列表页普遍**不给集数**（只有封面+标题）。
集数要进详情页，而详情页的选集列表多数是 **AJAX 懒加载**
（伍果的 `drama_catalog` 里服务端只渲染了第 1 个 tab "1-25"）。
所以判集数不能靠数列表，要靠第三节那个 `url` 空不空的判据。

归片那 63 处"集数线索"里最大值 2615、还有 725/698 —— 明显是**别的数字**
（时长、播放量、ID）被我的正则误捞，**不可信**。这也说明：
正则抠集数不靠谱，必须走播放页判据。

## 五、为什么这批源不值得继续投入

1. **唯一跑通的站只有 1 集** —— 剩下 3 个可解析的站要写专门适配器，
   而"适配器写完发现也只有 1 集"的概率不低（伍果就是这么个前车之鉴）；
2. **结构高度不一致** —— 4 个站要 4 套解析（`/vod/{id}.html`、`/nv/{id}.html`、
   `/hanxiaoquan/{id}.html`、`/p/66/d/{id}`），而且选集还异步；
3. **上游作者标注为"待验证"** —— README 里这些源几乎全带"待验证"，
   作者自己的口径是"功能优先、暂停集中测试"，说明他自己也没把握；
4. **对"能全部看"没有可验证的收益** —— 目前 0 个无墙全集源。

## 六、下一步该做什么（如果想继续）

**推荐：不再挖源站，改用"同类公开接口"的思路。**

七猫的公开接口（`xiaoqi.icofun.cn`）之所以好用，是因为它**本身就是个
把全集直链吐出来的服务**，而不是"需要逆向的源站"。找同类服务比逆向源站便宜得多。

判据（一句话，`tools/probe_wall.py` 已实现）：

```
对一部已知集数的剧，扫 nid=1..N：
  全部拿到直链            → 全集源，接
  第 K 集起 url 为空/404  → 有付费墙，跳过（伍果、红果都是这类）
```

**次选：只接"目录+搜索"，不接播放。**
网果/伍果/归片/韩小圈的目录是可解析的，可以当**发现层**用
（找剧、看简介、补封面），播放仍交给七猫。这样没有法律和稳定性风险。
但收益有限 —— 这些是盗版聚合站，内容质量与合规性都不如七猫（七猫带网微剧备案号）。

**不建议：照搬那 21 个源。** 那是别人几年的工作量（12 个源的适配器 + 异步选集 +
线路发现 + 每个源单独的签名），而且大部分标注"待验证"。

## 七、本轮产出的工具（可复用）

| 脚本 | 干什么 |
|---|---|
| `tools/probe_alive.py` | 批量探活：状态码/体积/标题/是否苹果CMS |
| `tools/probe_wall.py` | **核心判据**：扫 nid，看第几集开始拿不到直链 |
| `tools/probe_wall_many.py` | 多站批量墙扫描（含"sit 选错"反证） |
| `tools/probe_catalog.py` | 按上游真实路由抓列表页，看条目与集数线索 |
| `tools/probe_maccms_play.py` | 从播放页抠 `player_aaaa`，取分集直链 |
| `tools/probe_diag.py` | 诊断：dump 真实 URL 形态（我靠它纠正了"猜路径"的错） |

**踩过的坑（写下来免得重犯）**：
1. **不要猜 URL 模板** —— 我第一版 `probe_fullep.py` 全站未命中，
   因为苹果CMS 的搜索参数是 `?wd=` 而不是 `?searchword=`。必须先 dump 真实链接。
2. **不要把"id 不存在"误判成"付费墙"** —— 所以要先从首页确认 id 真实存在。
3. **不要用正则从列表页抠集数** —— 归片那次捞到 2615/725 就是反例。
4. **选集列表常是 AJAX 懒加载** —— 数不到不等于没有，要走播放页判据。
